# Triage — finalization

The user has approved the triage recommendations discussed above. Convert the
approved recommendations into a single structured proposal. Do not introduce
new tasks, new outcomes, new dependency edges, or new comment content that
the user did not agree to.

This is still a proposal-only step. Do NOT update Beads tasks, write GitHub
issues, or modify the repository. Sandcastle validates this proposal and
applies it after you emit it.

## Requirements

- Emit **exactly one** JSON object, wrapped in
  `<triage-proposal>...</triage-proposal>`. No prose outside the tag.
- Include one `decisions` entry per task you triaged. Do not invent task ids
  that were not in the prepared context.
- Each decision MUST have:
  - `taskId` — the Beads task id exactly as it appears in the prepared
    context (for example `bd-42`).
  - `outcome` — one of `needs_info`, `ready_for_agent`, `ready_for_human`,
    `wontfix`.
  - `category` — short string such as `bug`, `enhancement`, `task`,
    `question`, `documentation`, or another short tag matching the project's
    vocabulary.
  - `confidence` — one of `low`, `medium`, `high`.
  - `rationale` — one short paragraph explaining the recommendation.
  - `comment` — Markdown body to append to the task. Do **not** include the
    `> *This was generated by AI during triage.*` disclaimer; Sandcastle
    prepends it.
- `labels` is optional; list extra labels to add beyond the outcome label.
  Do not include the outcome label itself (Sandcastle adds it).
- `needsInfoQuestions` is optional and only meaningful when
  `outcome === "needs_info"`. When present, list the concrete questions the
  reporter must answer.
- `dependencySuggestions` is optional. Each entry expresses a
  "blocked by" edge: `dependentTaskId` is blocked by `blockerTaskId`. Both
  ids MUST appear in the live Hub board catalog from the prepared context
  (not stale ids from `.beads/issues.jsonl` alone). Do not create cycles or
  self-edges. Include a short `rationale` per edge.
- `summary` is required and gives a one-paragraph overview of the batch.

Keep recommendations honest about confidence: only mark `confidence: "high"`
when the evidence in the task body, comments, and dependencies makes the
outcome obvious. Sandcastle's `--yes` path applies only high-confidence,
non-closing, non-dependency-changing decisions; everything else will be
confirmed with the maintainer before it is applied.

```json
  "decisions": [

      "outcome": "needs_info",

      "outcome": "ready_for_agent",

      ]

```
