title: Manage tasks
description: Work with the local Hub task board safely.
---

## Initialize the task store

```bash
npx archloop tasks init
```

For a registered Hub project without a repository-local Beads database, this
creates the live store under the Hub project directory and installs a
Git-ignored `.beads/redirect`. Direct host `bd ready` and `bd show` then use
the same tasks as `archloop tasks`. Hub flow agents do not write that store;
they receive a read-only task snapshot and Hub applies any structured notes
after the attempt. An existing writer-free repository-local store migrates
automatically on `tasks init` and on the first mutating `archloop run` or task
command. The original database is quarantined, copied, verified, and retained
as a recoverable backup. If a writer, fingerprint change, unsafe snapshot, or
migration owner is present before quarantine, Hub keeps the legacy store and
retries later. Split brain after redirect stops automatic writes; inspect both
stores with `project status` or `tasks doctor` and do not delete either one
automatically.

A legacy task branch that committed allowlisted Beads runtime/export files can
still land. Hub strips only those paths from the merge candidate and records
them; Beads configuration, documentation, hooks, and unknown `.beads/**`
changes stay in the candidate.

## List and inspect

```bash
npx archloop tasks list
npx archloop tasks list --all
npx archloop tasks show <task-id>
```

Selectors are full Beads IDs or exact titles. Numeric list positions are not
stable selectors.

## Create and triage

```bash
npx archloop tasks create "Improve the login error"
npx archloop tasks triage <task-id>
```

New manual tasks enter the inbox. Triage proposes a status, description,
dependencies, and other collaboration changes before applying them.

## Create tasks from a PRD

```bash
npx archloop tasks from-prd <prd-ref>
```

The PRD flow validates a dependency-aware proposal and asks for approval before
writing local tasks.

## Diagnose and repair

```bash
npx archloop tasks doctor
npx archloop tasks repair-state <task-id>
npx archloop tasks recover <task-id>
```

Use `doctor` first because it is read-only. It can explain which historical
landing evidence was accepted or rejected. `repair-state` fixes the local state
projection when run events and task metadata disagree. `recover` handles failed
or interrupted execution while preserving recoverable branch work. Do not use
`tasks recover` for managed landing transactions or for legacy history that
startup already classified.

## Delete or clean branches

Preview destructive operations first:

```bash
npx archloop tasks delete <task-id> --dry-run
npx archloop tasks cleanup --dry-run
```

Task deletion affects local Beads data, not the linked GitHub Issue. Historical
unowned branches remain preserved unless cleanup is explicitly asked to include
them.
