---
title: Legacy repo-local setup
description: Maintain an existing custom workflow generated by archloop init.
---

`archloop init` is the compatibility path for repositories that own a custom
`.archloop/` orchestration scaffold. New users should use Hub onboarding.

## Create a scaffold

```bash
npx archloop init
```

The interactive setup selects a default agent, installed runtimes, sandbox,
backlog manager, template, project profile, and optional capability pack. It
creates an orchestration entry point, prompts, an environment example, and a
Dockerfile or Containerfile.

`init` refuses to overwrite an existing `.archloop/`. Back up intentional
customizations before replacing a scaffold.

## Configure credentials

```bash
cp .archloop/.env.example .archloop/.env
```

Fill only the variables required by the selected agent and backlog provider.
Never commit `.archloop/.env` or provider authentication data.

## Run the generated workflow

Use the package script created or recommended by the scaffold:

```bash
npm run archloop
```

The exact entry filename and sandbox preparation are template-dependent. Inspect
the generated `package.json` script and `.archloop/` files instead of assuming a
global command.

## When to stay on this path

Keep the repo-local path when your project depends on custom prompt processing,
templates, hooks, or a programmatic workflow. Adopt Hub separately when you want
shared project selection, task-board flows, centralized roles, and recovery.
