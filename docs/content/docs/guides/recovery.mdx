---
title: Recover interrupted work
description: Diagnose failed tasks, stale state, merge blockers, and preserved branches without losing work.
---

Start with read-only information:

```bash
npx archloop project status
npx archloop check
npx archloop tasks doctor
```

Then follow the CLI's recommended action.

## Interrupted run

Re-run the same flow first:

```bash
npx archloop run --flow <flow-id>
```

Startup detects tasks left in implementation, review, or merge without a live
worktree lease. Completed implementation or review events route the task to the
next stage, while preserved branch and worktree changes remain available. The
CLI reports each route; JSONL includes the structured `autoRecover` result.

To preview all interrupted tasks without starting a flow:

```bash
npx archloop tasks recover --stale
npx archloop tasks recover --stale --yes
```

The first command is a dry-run preview. Use `--yes` or interactive confirmation
to apply the batch recovery.

## Failed task

```bash
npx archloop tasks recover <task-id>
```

Recovery keeps branch work that can be retried and removes only safe managed
resources. Rerun the same flow after recovery when instructed.

## State projection drift

When `tasks doctor` reports that events and Beads metadata disagree:

```bash
npx archloop tasks repair-state <task-id>
```

Review the preview before confirming. This does not directly mutate GitHub.
`tasks doctor` remains read-only and groups interrupted, failed, stale, sync,
lease, and cleanup findings by severity.

## Dirty source checkout

Hub landing does not merge into the user's checkout. Overlapping uncommitted
files, staged Beads exports, and other WIP stay unchanged and do not block a
local landing onto the Hub publish target. After a successful landing, Hub
fast-forwards the configured host branch only when Git can prove that update
safe. Dirty, sparse, submodule, operation-in-progress, diverged, or otherwise
unsafe checkouts stay `checkout_sync_pending` and are retried automatically
on a later `archloop run`. Cleaning or switching the checkout is enough; do
not run `tasks recover`. Pending checkout sync never changes `shipped`.

Best-effort remote code publication is separate: when configured with
`--publish-policy best_effort` and `--remote-target`, network, credential,
protected-branch, or unknown push outcomes stay `target_publish_pending` and
retry automatically without undoing local shipped proof. Remote divergence
that changes the deliverable stays pending for fresh reconciliation instead of
force-overwriting. Discovering `origin` alone never enables publication.

A task branch that already committed allowlisted Beads runtime/export files
can still land: Hub removes only those paths from the candidate tree, records
every filtered path, and leaves the source branch and checkout unchanged.
Unknown `.beads/**` files are never dropped silently.

Interrupted landing transactions resume automatically on the next mutating
`archloop run`. Hub reconstructs progress from the journal, candidate
ref/manifest, verification artifact, atomic receipt, Beads close metadata, and
missing worktrees. `tasks doctor` and `project status` can show that pending
state without changing it. Do not run `archloop tasks recover` for this.

Pre-transaction history is classified the same way. Already closed tasks remain
completed. Ancestry-proven in-flight branches are adopted into a new
transaction on the next mutating run. A historical `merge_succeeded` event
never proves delivery. Missing or diverged branches are reported as
`legacy_landing_integrity` and are not closed or reimplemented.

A semantic merge conflict or verification failure is repaired automatically up
to two times. If that budget is exhausted, only that task becomes `blocked`
with `merge_conflict_unresolved` or `verification_failed`. Independent siblings
in the same batch still land. Transient Git lock, landing-lease, and I/O errors
stay pending and retry on the next run. If the Hub publish target moves before
landing, Hub invalidates that candidate, rebuilds on the new target, and
re-runs full verification. A live landing-lease owner is not displaced just
because a TTL elapsed.

## Active worktree lease

Wait for the active process or use the task recovery path. Do not remove lock
files, worktrees, or branches manually while a lease is active.

## Managed branch cleanup

```bash
npx archloop tasks cleanup --dry-run
npx archloop tasks cleanup --yes
```

The preview separates safe managed, blocked managed, and unowned historical
branches. Historical unowned branches stay preserved unless
`--include-unowned` is explicitly combined with confirmation.
