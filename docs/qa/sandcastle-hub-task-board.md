# Sandcastle Hub Task Board Manual QA

本文档用于人工验收 Sandcastle Hub task board 第一版。验收目标不是证明每个内部函数正确，而是确认用户能在一个真实 host repo 中完成 Hub 项目识别、Beads 本地任务管理、远端同步、flow 执行进度观察、merge/recovery 闭环，并且旧 `sandcastle init` 流程仍然可用。

## Scope

覆盖范围：

- `sandcastle project status`
- `sandcastle tasks list`
- `sandcastle tasks show <task-selector>`
- `sandcastle tasks create`
- `sandcastle tasks from-prd <prd-ref>`
- `sandcastle tasks triage`
- `sandcastle tasks sync`
- `sandcastle tasks comment <task-selector>`
- `sandcastle tasks recover <task-selector>`
- `sandcastle run . --flow <id>`
- Beads 本地任务状态、依赖、评论和 ready queue
- GitHub Issues 作为 remote task source 的 pull/push sync
- reviewer / no-review flow 的执行状态
- per-task merge events、verification gate、local Beads close
- legacy `sandcastle init` 兼容路径

不覆盖范围：

- GUI task board
- 多 remote task source 同时绑定同一 Beads task
- 自定义 flow registry
- Secret vault / keychain backend
- 非 GitHub 的 remote task source

## Test Environment

建议准备两个仓库：

- `SANDCASTLE_REPO`: Sandcastle 本仓库，用于运行 build/typecheck 和本地 CLI。
- `TARGET_REPO`: 一个独立测试项目，用于执行 Hub task board QA。

最低环境：

- Git repo 已有至少一个 commit。
- `bd` 在 host `PATH` 上可用。
- `gh` 已登录，并能访问测试 GitHub repository。
- 至少一个可运行的 agent runtime 已完成认证。
- Docker 或 no-sandbox 路径至少选择其一完成验证。

推荐环境变量：

```bash
export SANDCASTLE_REPO=/path/to/sandcastle
export TARGET_REPO=/path/to/target-repo
export TEST_GITHUB_REPO=owner/repo
```

从 Sandcastle 仓库构建本地 CLI：

```bash
cd "$SANDCASTLE_REPO"
npm install
npm run build
npm run typecheck
```

在目标项目中使用本地 CLI：

```bash
cd "$TARGET_REPO"
sandcastle --help
```

## Status And State Invariants

During every scenario, verify these invariants:

- `inbox` means task exists but has not been analyzed.
- `needs_info` means task is incomplete and waiting for reporter/user input.
- `ready_for_agent` means task is fully specified and AFK-suitable.
- `ready_for_human` means human-owned valid work.
- `blocked` means task is specified but blocked by dependency, auth, external system, or identified missing info.
- `failed` means execution failed and recovery is possible.
- `done` means branch merged, verification passed, and local Beads task closed.
- `wontfix` means local Beads task closed with wontfix marker.
- `sync_conflict` means local/remote semantic conflict needs human resolution.

Forbidden task statuses:

- `pending`
- `triaging`
- `waiting_for_review`
- `planning`
- `reserved`
- `claimed`
- `deferred`

Batch-only statuses:

- `planning`
- `partial_failed`
