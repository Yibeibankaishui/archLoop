Add an `interrupted_execution` diagnostic to `archloop tasks doctor` so a project inspected without re-running surfaces tasks stuck in an execution status (`implementing` / `reviewing` / `merging`) with no live worktree lease. The diagnostic fires for the released-lease cases the doctor was previously silent on — an `implementing` task with a stale (dead-PID) lease, and a `reviewing` / `merging` task with a claim and a missing or stale lease — by reusing the shared interrupted-execution detector, and dedupes against the existing `worktree_lease_missing` diagnostic so a task is never reported twice. It is `repairable: false`: the next action is `archloop tasks recover <id>`, not `repair-state`, so `archloop tasks repair-state` leaves it alone. The `nextAction` is enriched with the task's latest phase-completion event (read through the same wider selector `recoverHubTask` uses, so the doctor's suggested route matches the actual recovery route): a finished-phase event yields "review/merge already finished, recover to advance," and no event yields "implement was interrupted, recover to retry." The doctor remains read-only — it mutates neither lease files nor worktrees.
